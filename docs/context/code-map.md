# Code map

What each module in `src/quarry` and the verification scripts is responsible
for, which section of the design spec it implements, and which tests cover it.
Each stage adds a section for its packages.

## quarry

The top-level package holds the version, the config loader, failure helpers
shared by `quarry.kernel` and `quarry.data`, the licensed library statuses, and
the `quarry` command; `kernel.__main__` loads the config and `data.namespace`
builds from it.

| Module         | Responsibility                                                                                                                                                                                                                                                                                                   | Spec                     | Tests                      |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ | -------------------------- |
| `__init__.py`  | `__version__` only, a string literal the build reads as the package's one version.                                                                                                                                                                                                                               | §17 Repository layout    | `test_package.py`          |
| `cli.py`       | `quarry serve`: creates a missing root owner-only, picks a free port and a token, prints the SSH tunnel banner, and runs the app on `127.0.0.1` under uvicorn. `quarry projects list` and `quarry projects export <slug> [--out]` read the root's projects with no server running.                               | §12 Security, §10 Export | `test_cli.py`              |
| `config.py`    | `QuarryConfig` and its sub-models, `load_config` (reads `config.toml`, applies `QUARRY_MSSQL_DSN`), `api_key` (API env var or owner-only key file; native modes report CLI login), `ConfigError`. Native modes require an explicit model, reject API key files and anchor `cli_path`. Unknown keys are rejected. | §11 Config               | `test_config.py`           |
| `errors.py`    | `exception_message` (a `str(exc)` that survives a failing `__str__`) and `NOT_FAILURES` (exits and interrupts that failure guards must let through).                                                                                                                                                             | §13 Error handling       | none                       |

## quarry.query

A pure compiler from one `QuerySpec` to three targets (polars, DuckDB SQL,
Python source) with no import from `quarry.kernel` or `quarry.data`; the kernel
executor runs `to_polars` and `to_sql`, and `to_source` renders code a
researcher runs in the kernel.

| Module                   | Responsibility                                                                                                                                                                                                                                                                                                                                                                    | Spec                   | Tests                                                      |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- | ---------------------------------------------------------- |
| `query/__init__.py`      | Re-exports the public API listed in `__all__`.                                                                                                                                                                                                                                                                                                                                    | §7 Query spec compiler | none                                                       |
| `query/spec.py`          | Pydantic `QuerySpec` and its parts, `with_line_budget` for live/export cap parity, `row_order` for grouped-row order, with shape validation (for example `group_by` with `pivot` is rejected), plus `QueryError`.                                                                                                                                                                 | §5 Query spec          | `query/test_spec.py`                                       |
| `query/columns.py`       | `check_columns` and `check_output_columns` raise `QueryError` for a column the dataset lacks; `check_line_axes` validates temporal/numeric line types.                                                                                                                                                                                                                            | §7 Query spec compiler | `query/test_polars_target.py`                              |
| `query/polars_target.py` | `to_polars(spec, frame)` returns a `LazyFrame`, including whole-domain line reduction through the shared SQL reducer; `filter_expr`, `agg_expr` and `coerce_literal` build the expressions.                                                                                                                                                                                       | §7 Query spec compiler | `query/test_polars_target.py`                              |
| `query/sql_target.py`    | `to_sql(spec, relation)` renders one DuckDB statement; `line_sql` selects budgeted M4 representatives and null-run endpoints; `split_for_relation` splits a pivot spec into its SQL and polars parts; `first` and `last` raise `QueryError`.                                                                                                                                      | §7 Query spec compiler | `query/test_sql_target.py`, `query/test_line_reduction.py` |
| `query/source_target.py` | `to_source(spec, backing, result_name=, schema=, relation_projection=)` renders readable Python that assigns the result, takes only ASCII identifiers and raises only `QueryError`; the DuckDB form reads through the relation's importable projection and drops its temporary view in a `finally`. `result_names`, `imported_names` and `py_comment` serve "To code" and export. | §7 Query spec compiler | `query/test_source_target.py`                              |

`executor` compiles queries with `quarry.query`.
